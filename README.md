# Тернов Капитал

Сайт-визитка Ивана Тернова. Статический сайт с админкой. Публикуется через GitHub Pages автоматически при каждом изменении в ветке `main`.

## Структура

```
content/*.json        все тексты, фото и список документов (правятся через админку)
scripts/build.js      собирает страницу из шаблона и content/ в папку _site
styles.css, main.js   стили и поведение
admin/                админка (Sveltia CMS)
assets/uploads/       фото, загруженные через админку
files/                документы, загруженные через админку
```

Сайт пересобирается и публикуется сам после каждого сохранения в админке, примерно за 1–2 минуты.

## Админка

Адрес: `<адрес сайта>/admin/`

Что можно менять: главный экран (имя, строки под именем, фото), карточки опыта, услуги с фото, кейсы с фото и подробностями, полезные документы (загрузка файлов), контакты, текст и ссылку кнопки «Обсудить задачу», мессенджеры, тексты для поисковиков, текст плашки cookies, политику конфиденциальности (редактор с подзаголовками, жирным, ссылками и списками).

### Первый вход

1. Войдите на GitHub под аккаунтом, которому принадлежит репозиторий.
2. Откройте https://github.com/settings/personal-access-tokens/new
3. Название: «Админка сайта». Repository access: **Only select repositories**, выберите `ternov-capital`.
4. Permissions → Repository permissions → **Contents: Read and write**.
5. Нажмите **Generate token** и скопируйте токен.
6. На странице `/admin/` выберите **Войти с помощью токена доступа** и вставьте токен.

Браузер запомнит вход. Токен никому не передавайте.

### Как пользоваться

- Слева выберите раздел, справа поправьте поля, нажмите **Сохранить**.
- Фото: нажмите на поле фото и загрузите файл. Для главного экрана нужно горизонтальное фото, человек в правой части кадра, от 2400 px по ширине.
- Документ: раздел «Полезные документы» → **Добавить** → название и файл.
- Кнопки «Обсудить задачу», «Обсудить» в услугах, «Обсудить похожую задачу» в кейсах и «Оставить заявку» в контактах открывают форму заявки. В форме человек выбирает услугу из списка или «Другое». Если форму открыли из карточки услуги, эта услуга уже выбрана. В заявке также указан блок сайта, с которого её отправили.

## Заявки: Telegram и CRM

Сайт статический, поэтому заявки принимает маленькая функция в Yandex Cloud (`server/lead/index.js`). Она пересылает заявку в Telegram-бота и, если нужно, создаёт лид в Bitrix24. Серверы в России, бесплатного лимита Yandex Cloud хватает с запасом.

Пока функция не подключена, форма открывает письмо на почту из настроек с уже заполненной заявкой.

### 1. Telegram-бот
1. В Telegram напишите @BotFather → `/newbot`, задайте имя. Сохраните токен.
2. Напишите своему боту любое сообщение (или добавьте его в рабочую группу).
3. Откройте `https://api.telegram.org/bot<токен>/getUpdates`, найдите `"chat":{"id": ...}`. Это TELEGRAM_CHAT_ID.

### 2. Bitrix24 (необязательно)
Bitrix24 → Разработчикам → Другое → Входящий вебхук, права **CRM**. Скопируйте адрес вида `https://<портал>.bitrix24.ru/rest/1/<ключ>/`. Это BITRIX_WEBHOOK_URL. Заявки появятся в CRM → Лиды, источник «Веб-сайт», в описании источника указан блок сайта.

### 3. Функция в Yandex Cloud
1. https://console.yandex.cloud → Cloud Functions → **Создать функцию**, имя `ternov-lead`.
2. Среда выполнения **Node.js 22**, способ «Редактор», вставьте содержимое `server/lead/index.js` в файл `index.js`. Точка входа `index.handler`.
3. Переменные окружения: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, при необходимости `BITRIX_WEBHOOK_URL`, и `ALLOWED_ORIGIN` с адресом сайта: `https://tercptl.ru,https://www.tercptl.ru`.
4. Сохраните версию, включите **Публичная функция** в настройках.
5. Скопируйте ссылку вызова `https://functions.yandexcloud.net/...` и вставьте её в админке: «Контакты и кнопка» → «Адрес приёма заявок».

Проверьте: отправьте заявку с сайта, она должна прийти в Telegram (и в Bitrix24).

Другая CRM (amoCRM и т.п.) подключается правкой функции `toBitrix` в том же файле.

## Подключение домена .ru

1. В репозитории: **Settings → Pages → Custom domain**, впишите домен (например `ternov-capital.ru`), нажмите **Save**.
2. У регистратора домена (REG.RU, RU-CENTER и т.п.) в DNS-записях добавьте:

   | Тип   | Имя | Значение                         |
   |-------|-----|----------------------------------|
   | A     | @   | 185.199.108.153                  |
   | A     | @   | 185.199.109.153                  |
   | A     | @   | 185.199.110.153                  |
   | A     | @   | 185.199.111.153                  |
   | CNAME | www | `<логин-владельца>.github.io.`   |

3. Подождите от 15 минут до суток, пока обновится DNS. Затем в **Settings → Pages** включите **Enforce HTTPS**.

## Передача заказчику

**Settings → General → Danger Zone → Transfer ownership**, укажите логин GitHub заказчика. Сайт и история изменений переедут целиком. После передачи замените в `admin/config.yml` строку `repo:` на `<новый-логин>/ternov-capital`, иначе админка не найдёт репозиторий. После передачи адрес вида `*.github.io` сменится, а свой домен продолжит работать (проверьте поле Custom domain в Settings → Pages и CNAME-запись для `www`).
